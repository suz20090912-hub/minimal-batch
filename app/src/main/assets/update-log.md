## v1.3.0 — 2026-11-25

**主题**：App 自己会查更新了——但只有你点的时候才联网。

### 你反馈的 / 上一版留下的

- 每次更新都得自己去 GitHub 找 Release 下载，装完还要手动确认版本对不对。
- 国内直连 GitHub 常常连不上，希望有备用线路，而且能先测速再决定走哪条。
- 有些网络必须走代理，希望能自己填。
- 定过的规矩：只在手动点击时联网，点了先弹确认框，确认后不能跳走。

### 改法（先把行为说清楚）

- 设置 tab 里**单独一个「检查更新」条目**，点进去才是更新中心：不自动弹窗、不挤占别的页面。
- **只有点「获取更新」才联网**；点了先弹确认框（写明接下来要联网、不会自己装、不会后台上传），确认后才开始。
- 确认后**不跳转**：先判镜像站可用性与速度 → 再读 `version.json` → 比 `versionCode` → 有新版才出下载按钮。
- 失败给**分类提示**，不是一句"失败了"：「无法获取版本信息」「连不上镜像站」「镜像站响应较慢」「下载中断」分开说。

### 新增

- **镜像站**：内置三条（jsDelivr / ghproxy / GitHub Raw），另可填自定义地址；支持「自动选最快」或「手动指定」；每行可单独测速，显示毫秒或"连不上"。
- **代理**：HTTP 代理 host / 端口，只作用于检查更新与下载，关掉开关即恢复直连。
- **下载与安装**：显示下载进度百分比 → 完成后按钮变「安装已下载的安装包」→ 交系统安装器（需要你允许"安装未知应用"），不静默安装。
- 更新中心底部三步说明（连镜像站 → 读版本 → 下载），当前走到哪一步有勾选反馈。

### 已知不足

- 自定义输出目录的成品仍不进系统相册（媒体扫描兜底还没做，留下一版）。
- 成品页只看当前输出目录，还不能切换位置。
- 没有"启动时静默检查更新"——刻意的，避免偷偷联网。
- 三条镜像站在不同网络下速度差很多，得靠你实测反馈哪条最稳。

## v1.2.8 — 2026-11-25

**主题**：看图能左右滑了，像原生相册一样翻上一张 / 下一张。

### 你反馈的

- 从成品里点开一张图后不能左右滑，只能退出去重新点；图多了翻起来很费劲。
- 退出再点别的图时，还担心会不会跳错位置。

### 改法

- 看图页改成**横向翻页**：手一滑就到下一张 / 上一张，滑到头就停住，不会乱跳。
- 顶栏文件名下面加一行 **"第几张 / 共几张"**（如 3 / 12），随时知道自己在哪。
- **1× 时滑动=翻页；放大后（>1×）滑动=图内平移，不会误翻页**；缩回 1× 才恢复翻页。
- 编辑不受缩放影响：放大着也能直接点「编辑」，编辑保存后回到当前这张。
- 退出看图回到成品页时，网格**保持原来的滚动位置**，不会跳回顶部；点哪张就停在哪张。
- 切图时上一张的缩放会自动复位，避免带着放大状态看下一张。

### 已知不足

- 编辑保存会再编码一次，有轻微画质/体积损失。
- 单张图加载有极短空白（切图时会现场解码），大图比小图稍慢一点。

## v1.2.7 — 2026-11-25

**主题**：修看图/编辑页的触摸穿透——点空白会莫名打开另一张图。

### 你反馈的

- 编辑页里点上面的"编辑"几次，就跳到另一张图；那张图看起来像手机原生相册，又确实是我们 App 里已经转换过的图片。问是不是特意做的。

### 根因

不是设计，是 bug。看图/编辑页浮在整个 App 上面，但页面里**只有有按钮的地方才接触摸**，顶栏中间的"编辑"只是一行标题、图片在编辑态也没接手势；点在那些空白处，触摸就穿透到下面的成品网格，把那格的图打开了。

你看到的那张"原生相册"其实是**你自己截的一张相册截图**，它被当成品处理过（就是列表里 1080×1080、1.9MB→103KB 那张），所以在全屏打开时看起来像相册界面。图片是真的成品，不是跳去了别的 App。

### 改法

- 看图/编辑页最底层加一层**全屏触摸拦截**，落在页面上的点击不再往下漏；点空白只当作点空白。
- 顶栏中间的"编辑/裁剪"从白色 15sp 降成灰色 13sp，明确是**标题不是按钮**，不会再让人以为能点。
- 其余布局、裁剪、详情、保存逻辑不变。

### 已知不足

- 编辑保存会再编码一次，有轻微画质/体积损失。
- 暂不支持左右滑动切上一张 / 下一张。

## v1.2.5 — 2026-11-25

**主题**：修裁剪划不动；看图 / 编辑界面按原生相册重排。

### 你反馈的

- 裁剪根本划不动，划了也起不到作用。
- 返回、编辑这块 UI 布局不合理，想照手机原生相册那套来。

### 根因（三个叠在一起）

1. 裁剪框的位置状态只从外面传进来，手势里读到的永远是"打开裁剪那一帧"的旧矩形，每帧只加一个很小的位移，下一帧又从旧值算起——框被反复拽回原点，看起来就是划不动。
2. 只有按住四角 120px 内才算命中，手指按在框中间拖根本没有分支，自然没反应。
3. 顶栏按钮散在两端、编辑底栏用药丸按钮，跟系统相册（左返回、中标题、右操作，底栏图标在上文字在下）不是一套。

### 改法

- **裁剪状态挪进裁剪组件内部**保存，拖动真正跟手；四角手柄命中半径 **56dp**，按住即变紫；**框内任意位置可整体平移**，点框外空白不动，避免误触。
- **顶栏**：左侧圆形返回按钮 + 中间文件名，压在渐变蒙层上。
- **底栏**：分享 / 编辑，图标在上、文字在下，和原生相册同一结构。
- **编辑顶栏**：取消 / 编辑 / 保存（保存用高亮色）；**编辑底栏**：左转 / 右转 / 镜像 / 裁剪 / 还原。
- **裁剪顶栏**：取消 / 完成，底部一行“拖四角缩放范围 · 框内拖动可整体移动”。
- 点一下画面隐藏全部按钮、再点一下回来，保持不变。

### 已知不足

- 编辑保存会再编码一次，有轻微画质/体积损失。
- 暂不支持左右滑动切上一张 / 下一张。

## v1.2.4 — 2026-11-25

**主题**：看图页换成系统相册的手感，并补上最基础的编辑。

### 你反馈的

- 截图里的"分享"不仔细看根本看不见，按钮像跟照片融在一起。
- 想要系统相册那种：点开就是照片，点一下清屏只剩照片，再点一下把分享/返回/编辑叫回来。
- 顺便把编辑也一起做。

### 根因

旧版顶部只有三颗**透明文字按钮**直接压在照片上，没有底色也没有分区，底图一花就看不出来了；文件名还跟按钮挤在同一行。

### 改法

- 顶部换成**实心药丸按钮**：`‹ 返回` / `编辑` / `分享`，深底 + 1dp 白描边 + 纯白字，压在任何照片上都清楚；文件名单独一行放按钮下面。
- **点开默认显示按钮 → 点一下画面全部隐藏只剩照片 → 再点一下回来**，和系统相册一致。
- 新增**编辑**：左转 90° / 右转 90° / 镜像 / 裁剪 / 还原。裁剪是拖四角，带九宫格辅助线，框外压暗。
- **保存另存新图**：`<原名>_edit_<时间>.jpg`，JPEG q92，存回当前场景文件夹，**不覆盖原图**；保存后成品页自动刷新。
- 编辑载入按最长边 **4096**，超大原图会先缩到 4096 再编辑，避免爆内存。

### 已知不足

- 编辑保存会再编码一次，体积和画质有轻微损失（裁剪/旋转无法做到无损）。
- 还不能左右滑动切上一张 / 下一张。

## v1.2 — 2026-11-25

**主题**：结构与安全感。只改"用得顺手"的部分，不加任何新的处理能力。

### 修掉的问题

| 反馈 | 根因 | 改法 |
|---|---|---|
| 手滑一下手势返回就退出，回来得重新选几十张图 | 根页面的返回直接 `finish()`，选图只活在内存里 | ① 有未完成工作时，返回先弹确认框（取消/退出）；② 正在处理时返回被挡住，只提示 `正在处理 N/M`；③ 选图列表落盘 + `takePersistableUriPermission` 长期授权，冷启动自动恢复上次的选图，已被删掉的图静默剔除 |
| PNG 透明底转 JPEG 变成黑块 | JPEG 不支持 alpha 通道，透明区被填成黑 | 编码前先合到白底（`flattenOnWhite`）；预览也走同一条路，所见即所得 |
| 处理完只知道目录名，得退出 App 自己翻 | v1.1 只有一个结果卡 + 文字路径 | 成品页：按场景分组的网格，点开全屏，右上角可交给系统看图应用 |

### 新增

- **底部三个页面**：转换 / 成品 / 设置。切页不影响处理，进度条在转换页继续走。
- **成品按场景分文件夹**：`Pictures/极简批处理/微信发送`、`/存档原图`、`/社交方图`。不依赖数据库，扫目录就能分类；系统相册里也会多出这三个相册。v1.0 留下的平铺老图归到「未分类（旧版）」。
- **输出位置可改**：默认还是 `Pictures/<文件夹名>`，文件夹名可改；也可以用系统文件夹选择器选任意目录（SAF，长期授权）。换位置只影响以后的处理，老图不动。
- **设置页**：默认场景、输出位置、清空已选、关于（版本 / 协议 / 权限声明 / 项目主页）、**离线更新日志**。
- **更新日志内置**：`assets/update-log.md`，和仓库里的 CHANGELOG 同源，装机后不联网也能翻版本记录。

### 已知不足

- 选到自定义文件夹后，系统相册不一定索引这些图，请在 App 的「成品」页看。
- 成品页只列当前输出目录；换过位置后，旧目录里的图不会出现在列表里（文件本身还在）。
- 还没有联网检查更新 —— 排到 v1.3，且只在你手动点击时才联网。

### 修掉的问题

| 处理完只知道目录名，得退出 App 自己去找 | v1.0 结果卡只显示文字路径 | 结果卡加「看这批图」：双列成品网格 → 点图全屏 → 右上角「相册」把第一张交给系统看图应用 |

### 新增

- **选图即时预览**：选完图或切换场景，按当前预设**真跑一遍**（解码 → 缩放/裁方 → JPEG 编码），结果只留在内存做缩略图、**不写盘**，生成「原图 → 处理后」对照卡片，附目标尺寸和**预计体积**（如 `1920×1440 · 预计 412KB`）。单张约 115ms，3 路并行，一次最多预跑 20 张。
- 原图列表每行也补上「预计体积」，和预览卡片对得上。
- `applyTargetSize()` 从正式处理里抽出来，预览和正式处理共用同一套尺寸计算，避免「预览说 1920、实际出来 1800」。

### 已知不足

- 预览上限 20 张，超出的部分只有尺寸估算，没有缩略图。
- 成品相册只显示当前这一批（v1 没有历史记录）。
- 视觉仍是最朴素的，美化排在后面。

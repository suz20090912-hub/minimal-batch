## 一、这是什么

一个完全离线的 Android 批量图片处理工具，给做内容、发图文的人用：选一批图 → 选场景 → 一键压到合适尺寸/体积 → 直接写进相机的相册文件夹。

三条底线：不登录、不联网处理、图片不上传。完全开源免费，不设赞助渠道，也没有付费版。

技术底子：Kotlin + Jetpack Compose，minSdk 29 / target 35，包名 `dev.localbench.batch`，正式签名密钥在 `release-key/minimal-batch.jks`（已交付，务必自行备份，丢了就没法覆盖升级）。

## 三、已经定下来的设计（别再来回改）

- **返回层级**：一层一层退——全屏图 → 更新中心/公告/更新日志 → 非转换页回转换页 → 根页才问退不退。选择模式、移出模式这类临时态，返回只退出该模式。
- **成品组织**：场景即子文件夹，零数据库；`Pictures/极简批处理/<场景名>`，或用户自选 SAF 目录。
- **输出位置**：默认 Pictures 下可改名，也可选别的文件夹；换位置只影响以后，老图不动。
- **删除入口**：只放两处——成品页长按多选删、看图页右上单张删；结果卡不再有删除按钮。
- **更新检查**：仅手动触发、确认框先行、镜像站优先、内置 6 条列表 + 测速 + 自动/手动 + 代理；错误分类；单独条目在设置里。
- **公告编号**：`NoticeStore.ID` 改大就让人重新看到小圆点，v1.4.0 起 1 → v1.6.2 起 8。
- **节奏**：一版只加一类能力、每版真机验收、每版发 Release、每版 push 源码。

## 四、最近几版的细节

### v1.6.0：选图回到看原图

- 以前选完图会按预设真跑一遍生成“处理后的样子”，费时间也吃内存。整排预览卡连同进度条一起去掉。
- 改成 3 列原图网格，每格是缩略图 + 体积，总览一行“已选 N 张 · 共 X”。
- 点原图进看图页：左右翻页、双指缩放、右上 ⓘ 看文件名/尺寸/大小/格式/位置；**只读**，底部分享/编辑整行不出现，右上删除也不出现。
- 成品页处于选择模式时按返回，先退出选择，不再一跳回转换页。

### v1.6.1：结果记录能自己清

- 结果卡底部两个按钮：「展开每张明细」「清除记录」。清除只把这条记录从会话里拿掉，回到选图状态，一张图片都不删。
- 设置里「清空已选图片」也会顺带把记录清掉，不会再出现选了空、卡还挂着。
- 更新日志重排：正文 12 → 15 号字、行距 25、标题分三级；`**`、反引号、`---` 不再原样显示；版本表格在 App 内不渲染（窄屏会挤成一团），完整表格仍留在仓库 CHANGELOG。

### v1.6.2：不转的那张，长按移出

- 选图网格长按任意一张，进「移出」模式：长按那张默认已勾，再点几张加减，顶部「移出 / 取消」。
- 点「移出」只改这批名单，原图不动、不删、授权不动，剩余张数和总体积立刻变。
- 移出模式里按返回只退出该模式，不会把选好的全丢。
- 全移空时网格位置显示“这批已经空了，点上面的「选择图片」重新挑”。

### v1.7.0：按体积压 + WebP

- 转换页加了一排体积档：不限 / ≤500KB / ≤2MB / 自定义（50～10240KB 自己填）。
- 真压链路：按预设先编码，超线就逐档降质量（每档 8，最低 q40），还超就缩尺寸（×0.85，最多 4 轮，长边不低于 640）。
- WebP 开关：`WEBP_LOSSY`，API 30 以下自动回落 JPEG；带透明通道走 WebP 时不再合白底。
- 后缀与 mime 跟着格式走（`.webp` / `.jpg`），MediaStore 和 SAF 两条写入路径都改了，相册不会认错。
- 结果卡标出这批用的体积档与格式。

### v1.9.0：一批没跑完，接着跑

- 新文件 `ResumeStore.kt`：`filesDir/batch_resume.txt`，第一行表头（uris / preset / targetKb / webp / prefix / total / at），之后每完成一张追加一行 `Done`；追加写加 `synchronized`，进程被杀最多丢最后一张。
- `BatchEngine.runBatch` 增加 `resume: Map<Int, Done>` 与 `onItem`：已完成的下标不进信号量，`items` 最后按 index 排序合并，结果卡仍是完整一批。
- `Session.start`：uris 与 preset/targetKb/webp/prefix 全等才续，否则清旧断点起新批次。
- `Session.init`：冷启动读断点并与 `K_SEL` 比对，对不上直接清；对上则置 `resumeDone/resumeTotal`。
- 转换页按钮下方多一行："上一批没跑完：已完成 M/N 张，点「开始处理」会跳过做完的那 M 张接着跑"。
- `setPicked` / `removePicked` / `clearPicked` / `resetPage` 四处都清断点；`cancelRun` 有意保留。
- 顺带删掉设置页「默认场景」整卡（重复入口），`SettingsScreen` 不再 collect 会话状态。

### v1.8.1：后台线程弹 Toast 必崩

- 现象：v1.8.0 点「导入文件夹」→ 选目录 → 确定 → 必定闪退回桌面。
- 原因：`importFolder` 跑在 `Dispatchers.IO`，收尾的 `Toast.makeText(...).show()` 在无 Looper 线程执行，Android 11+ 直接抛 `RuntimeException`；`SupervisorJob` 没配 `CoroutineExceptionHandler`，异常直冲默认处理器，进程死。成功和空文件夹两条路都要弹一次，所以必崩。
- 改法：`Ui.kt` 的 `toast()` 线程安全（非主线程转投 `Handler(Looper.getMainLooper())`），并统一 `applicationContext`；`importFolder` 整段 `try/catch/finally`；`FolderScan.collect` 对 `walk` 兜一层 `runCatching`。
- 新增 `Crashes.kt`：`Thread.setDefaultUncaughtExceptionHandler` 记录堆栈到 `filesDir/last_crash.txt`（写版本号与线程名），设置「关于」里崩过才出现「上次崩溃日志（点击复制）」。

### v1.8.0：整个文件夹一次拿进来

- 转换页「选择图片」旁边加「导入文件夹」，走 SAF 树选择器（`OpenDocumentTree`），`Session.importFolder` 接手。
- 扫描逻辑在新文件 `FolderScan.kt`：直接用 `DocumentsContract` 批量查子项，一层一次 query，不引 `androidx.documentfile`。递归上限 6 层，`image/*` 优先，mime 缺失时按扩展名兜底（含 heic/heif/dng）。
- 语义是追加：`旧 + 新` 去重写回 `K_SEL`，手选的几张不会被冲掉，可以叠多个文件夹。
- 单次上限 2000 张；读取按 24 张一批喂给 `inspectAll`，避免几千张并发解码。
- 新增 `importing` / `importMsg` 两个状态：扫描时显示"已找到 N 张"，读取时显示"x/y 张"，期间三个按钮禁用、网格位置显示"正在导入文件夹，稍等…"。
- 按钮布局随之调整：`选择图片` / `导入文件夹` 并排一行，`开始处理` 单独整行（主操作更醒目）。

## 六、工程与交付流程

Windows 上没有 git / JDK，所以流程固定成这样：

1. Windows 改源码与文档 → 打包 `batch-app.zip`
2. 上传 CDN 拿一个临时直链
3. 切 Linux 云主机：下载解压到 `~/ktcheck/batch-app`，补 4 处构建配置（`buildToolsVersion`、`gradle.properties` 内存与并行、`local.properties`、`keystore.properties`），`gradle assembleRelease`（JDK17 / Gradle 8.9，约 2 分 15 秒）
4. APK 上传 CDN 回传 Windows（校验字节数与 SHA-256）
5. `present_files` 交付安装包
6. GitHub 走 REST 增量推 blob/tree/commit（`push_files.ps1`），先建 tag ref → 建 Release → 上传资产（asset）→ 最后改 `version.json`
7. 每次都核对：开发工程 `batch-app/` 与仓库镜像 `minimal-batch/` 同名文件哈希一致，否则会推旧代码

踩过且要记住的坑：Gradle Kotlin DSL 里 `java.util.Properties()` 会被当成 Gradle 的 `java` 扩展（要显式 import）；`EnterTransition` 与 `ExitTransition` 不能混用；PowerShell 单引号里的 `` `r`n `` 不转义；`$变量:` 紧跟冒号要写 `${变量}`；部分源码 CRLF 部分 LF，多行替换要用 Edit 工具而不是字符串 Replace。

## 七、已知限制

- 删除没有回收站，删了就是删了。
- 选图网格只显示原图体积，看不到“处理后会多大”，要估体积得先去成品页。
- 结果记录只存在内存里，冷启动就没了（有意为之，避免下次打开还挂上一批）。
- 体积搜索是启发式（降质量 + 缩尺寸），极复杂的图可能仍略超目标；WebP 在微信、部分图床不友好。
- 移出图之后原授权记录还留着，不影响使用，只是没做回收。
- 非主存储卷（SD 卡、网盘目录）的写入没法用 MediaScanner 兜底，只能靠成品页找到。
- 仓库 `screenshots/` 仍是占位，等四张实机截图。
